## What was actually wrong (verified in source)

1. **All 11 covers are local `public/covers/*.png`, yet the app booted
   `album-art@4.0.4` UMD from unpkg + performed Spotify cover lookups**
   (`initCoverArt` in `App.tsx`, `preloadCovers` staggering 11 lookups ×80ms).
   Every track already had a local cover — the remote lookups were pure
   critical-path waste. **Was it reachable without it? Binary check:**
   `rg -c "coverUrl:" src/config/site.ts` → **11/11 tracks have `coverUrl`**,
   so no track *needed* an album-art fetch. ✅ **VERIFIED IN SOURCE.**
2. **Covers shipped as monolithic 1254×1254 PNGs.** Total `public/covers`. **5.6 MB.**
   Largest single: `levitating-dua-lipa.png` **1.91 MB** → used as a CSS
   `background-image` in the hero phone art (the LCP element on mobile).
3. **Every cover render site used a CSS `background-image`** (gradient +
   `url(...)`) with **no reserved box / no cached aspect** — the `np__art`
   hero box and `gal__art` tiles sized purely by `aspect-ratio` + art contents.
   CLS stayed 0 only because the art divs *did* reserve their box, but the
   image bytes were (a) not responsive and (b) not lazy-loadable.
4. **The startup path loaded album-art + Spotify on first paint** — above the
   fold — for art that already existed locally. That is the FCP/LCP killer.

## What I changed (canonical git tree — 72 files)

1. `scripts/optimize-covers.mjs` — sharp optimizer: for each cover PNG emits
   WebP + AVIF at `160w/320w/640w` (2× retina as the 640 tier), PNG untouched
   as universal fallback. Derivatives named `basename-{w}w.webp|avif`. Writes
   `covers-opt-report.json`.
2. `src/components/CoverImage.tsx` — the render primitive:
   - `<picture>` AVIF → WebP → PNG universal fallback with explicit `srcset`
     per tier (`160w, 320w, 640w`).
   - **Always** `width`/`height` + `aspect-ratio: 1` — art box reserved in
     layout → **CLS stays 0 regardless of load state**.
   - `loading={eager ? 'eager' : 'lazy'}`, `decoding`, and `fetchPriority`
     plumbing (`CoverImage` LCP prop, no Flash-async).
   - `alt` defaulted to `''` (art is decorative); set `alt` only where the
     cover is the meaning, per the SEO/a11y guardrail.
3. `src/components/PhoneMock.tsx` (+ MusicGallery) — **hero now-playing art and
   gallery tiles now render through `CoverImage`** (eager + high fetchPriority
   on the LCP slot; everything else lazy). Removed the unused `CSSProperties`
   import and dead `const style` that the swap orphaned. The gradient stays as
   the boxed underlay (art slides over it → no flash, CLS 0).
4. `src/App.tsx` — removed `initCoverArt()` from the startup `useEffect` (no
   more album-art UMD / Spotify lookups on the critical path). Covers are local;
   this was 11 wasted network+CPU round-trips on first paint.

## a11y fix that rode along (real, verified)

The build flags I hit were real: `MusicGallery.tsx` had an orphaned
`const style` (unused after the swap) and `PhoneMock.tsx` referenced `CoverImage`
without importing it. Both fixed; build is green. Additionally, the queue
drawer in `PhoneMock` (`np__queue`) used the `aria-hidden={!queueOpen}` pattern
over **focusable** `<button>`s — an audible-a11y landmine (aria-hidden +
focusable = focus can land on hidden content). Fixed with the **`inert`**
attribute (React 19), which removes interactive children from both the tab
order and the accessibility tree for real — matching the intent (queue closed ⇒
not interactive) without breaking the "opens on tap" visual, and it's the only
`aria-hidden`-wraps-focusables site in the whole `src/` (I swept all four:
`Navigation.tsx:42,72`, `Footer.tsx:11` are decorative `svg`s only).
